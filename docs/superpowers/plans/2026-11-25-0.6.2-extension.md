## Review Focus

- The key is replaced or deleted while `/v1/me/access` is in flight: the panel shows the new key's data, never the old.
- The user edits the English field while its translation is in flight, or types a translation of their own meanwhile: nothing of theirs is overwritten.
- A phrase with the same word twice, a newline, curly quotes, emoji, `__`, `<b>`, `[sound:x]`, `{{c1::x}}`: the note's fields are what the spec's table says.
- Anki closes between the model check and addNote, with Flibooster running: a visible error, no note in the collection file.
- A half-finished upgrade from an earlier failed save: finished on the next save, not called a user edit.

### Task 3: key access client

**Files:** Create `ext/js/data/flib-key-access.js`; modify `ext/js/comm/flib-gateway-client.js`, backend, api, types. Tests: `test/flib-key-access.test.js`, client and backend tests.

**Produces:**

```
KeyUsage = {used: number, limit: ?number, unlimited: boolean}
KeyAccess = {keyPrefix: ?string, expiresAt: ?string, demo: boolean,
  rights: {id: string, usable: boolean, permanent: boolean, validFrom: ?string, validTo: ?string}[],
  gpt: ?KeyUsage, tts: ?KeyUsage, stt: ?KeyUsage, resetsAt: ?string,

```

Parsing: units from `used_microusd/limit_microusd` (gpt), `used/limit` (tts chars, stt seconds); `limit` null or `exempt` → unlimited; a wrong type, negative or non-finite number → that usage is null; `demo` true unless exactly `false`; `key_expires_at` absent → null (no expiry), present but unparsable → null plus no crash — and it must NOT read as «бессрочно»: use `expiresAt: ''` for unparsable and test it; capabilities without a string id are skipped; `usable_now` missing → `active_now`. Not an object or no `capabilities` array → null → `flib_key_access_unsupported`.
Errors (trim the text body, compare exactly): 401 → `flib_key_invalid`; 403 `API key revoked` → `flib_key_revoked`; 403 `API key expired` → `flib_key_expired`; other 403 → `flib_service_unavailable`; 404/405 → `flib_key_access_unsupported`; 429/5xx → `flib_service_unavailable`; network/timeout as today. Read at most 64 KB of body. GET, `cache:'no-store'`, no extra headers, key only in Authorization.

- [ ] Tests first: the spec's example, optional fields absent/present, every error row, oversized body, HTML body with 200, `usageShare` (0, 0.4 %, 37 %, 99.6 % → left 1, over limit, limit 0 → unlimited is decided by null/exempt only: 0 with no exempt → exhausted), no key → `flib_key_missing` without a request; content-script sender refused; nothing logged.
- [ ] Commit `feat(gateway): read the key's rights and usage`.
