# 0.6.2: карточка Phrases из окна фразы, с видео

Дата: 2026-11-25. Порядок владельца: «изменения в плагин и типы карточек первоначально добавляем в Flibooster, потом уже используем у себя». Задача Flibooster #437.

## Зачем (слова владельца)

- «Видео из окна делать», «Предлагаю в этом случае делать карточку с типом Phrases… Туда не хватает: полей для youtube»;
- «если у пользователя выделена часть фразы, то её считаем пропуском, если не выделена, то показываем всю фразу целиком без пропуска»;
- «Мы работаем только со своей колодой».

## Не цели

Старые карточки фраз (тип «Yomitan Card Type») не переделываются. ReverseDeck, Yomitan Card Type и плагин голосового ввода не меняются. Параллельная правка одной карточки не обрабатывается.

## A. Flibooster (anki_conf, worktree, PR в x2-2/turmalin; слияние — по слову владельца)

1. `internal/ankimodels/models/Phrases.json`: поле `flib_media` ПОСЛЕДНИМ. На обороте `<div class="flib-media">{{flib_media}}</div>` сразу после закрытого `.hero`; на лице — нет. CSS-блок `.flib-media` дословно из «Yomitan Card Type». Без метки ревизии в JSON.
2. Карточка без пропуска: в тексте Front нет `_{2,}`.
   - Лицо: подпись «вспомни перевод»; нет поля ввода, подсказки и списка ответов; вся фраза.
   - Оборот: подпись «фраза»; фраза один раз; перевод; озвучка; видео.
   - Карточка с пропуском не меняется ни на байт поведения, кроме п. 3.
   - ⚠️ Такие карточки уже бывают: `createPhrasesCard` и обогащение расширения оставляют целое предложение, когда слово не найдено, а EnglishWord при этом = слово. Признак лица — только отсутствие пропуска; признак «фраза один раз» на обороте — EnglishWord равно Expression.
3. Ввод ответа: «Well, I know.» засчитывается с пунктуацией и без неё. Сравнение: и ввод, и ответ без знаков `, . ; : ! ? …`, с одинарными пробелами; прежние ответы по частям продолжают засчитываться. Сущности (`&amp;`, `&#39;`) не режут ответ.
4. Будка: признак «пропуск» = Phrases и `_{2,}` в показываемом тексте. Без пропуска подпись «прочитайте фразу вслух» / «read the phrase aloud» (новый ключ i18n), наведение-словарь выключено. `pronunciation/sides.go`: без пропуска RU = ExpressionTranslate (без HTML), иначе как сейчас.
5. Тесты (по образцу `TestYomitan…` для `flib_media`), устаревший `deploy/anki-bootstrap/README.md`, `docs/ref/card-enrichment-and-pos.md`. Проверка в изолированной Anki 26.05, день и ночь: с пропуском, без, с плеером, с клипом, со старым списком ссылок.

EnglishWord никогда не пуст: пустой плагин голосового ввода считает сломанной карточкой и засчитывает любой ответ.

## B. Расширение

### Что записывается

| Поле                           | Есть выделение                        | Нет выделения    |
| ------------------------------ | ------------------------------------- | ---------------- |
| Front                          | фраза, выделенный кусок → `_____` (5) | вся фраза        |
| EnglishWord                    | кусок                                 | вся фраза        |
| Expression                     | вся фраза                             | вся фраза        |
| ExpressionTranslate            | поле «Перевод»                        | поле «Перевод»   |
| flib_media                     | отмеченные видео                      | отмеченные видео |
| Audio_expression / Audio_front | озвучка, см. ниже                     | озвучка          |

- Тип всегда Phrases. Колода — формата карточки, которым окно пользуется сейчас (первый формат терминов); если её нет — «Flibooster». Теги — как у нынешней записи фразы, плюс `flib_enriched` (иначе Core вернёт 400 и попробует обогатить). Тег `<id>_phrases` не ставится.
- Выделение берётся в момент нажатия из `PhraseSelectionMemory` (фокус уходит на кнопку). Пропускается ИМЕННО выделенное место, а не первое такое слово. Границы: расширить до целых слов, убрать пробелы и знаки по краям. Выделено всё поле, только знаки или нет латиницы — выделения нет. Пробелы и переносы фразы — в один пробел. Подчёркивания самой фразы (`__` и больше) заменяются на одно, чтобы не стать пропуском. Всё экранируется (`escapeHtml`), сущности выбираются так, чтобы шаблон Anki показал исходный текст.
- Кнопка «В Anki» в подсказке говорит, что будет: «пропуск: …» или «вся фраза».

### Перевод и озвучка

Карточка создаётся сразу. Затем, если обогащение включено и ключ есть: озвучка Audio_expression (вся фраза) и Audio_front (пропуск → пауза, как сейчас; без пропуска Audio_front пуст, чтобы карточка не читала ответ дважды) и перевод, если поле «Перевод» пустое (тот же запрос и кеш, что «?»). Сбой этого шага карточку не портит и виден строкой состояния, как у слова. Без ключа или без обогащения — только то, что в окне.

### Видео

Правила Task 8 плана 2026-11-24 действуют с типом Phrases: панель окна фразы получает сохранение; тексты подвала — про фразу; YouTube и фильмы одинаково; ошибка подготовки или нет поля → ничего не сохраняем, галочки остаются; нажатое сохранение всегда завершается (смена слова, закрытие); галочки снимаются после успеха; двойное нажатие — один раз. Фраза уже сохранена: подвал обновляет ТОЛЬКО `flib_media` первой найденной заметки, с проверкой колоды и типа, слиянием `mergeFlibMediaFieldHtml`; сбой чтения — ничего не пишем. Ничего не отмечено — `flib_media` пустое, дополнительных запросов нет. Тексты `anki.phraseNoVideo` и `video.phraseViewOnly` удаляются.

Найденная заметка — по Front (первое поле), как сейчас ищет Anki, среди заметок Phrases этой колоды. Смена выделения или текста возвращает кнопку «В Anki».

### Обновление типа у тех, у кого он уже стоит

Сейчас расширение чужой шаблон не трогает, а установка отмечена флагом без версии. Новое поведение — ТОЛЬКО для Phrases и ТОЛЬКО при первом сохранении из окна фразы:

1. Типа нет → создать (новая версия).
2. Поле `flib_media` есть, шаблоны и CSS равны новой версии → ничего.
3. Шаблоны и CSS (с `\r\n`→`\n`, без метки) равны ЛЮБОЙ прежней канонической версии → добавить поле в конец, обновить шаблон, CSS и метку.
4. Иначе пользователь правил шаблон → добавить только поле, шаблон не трогать, один раз сказать: «видео сохранено в поле flib_media, но ваш шаблон Phrases его не показывает».
   Прежние канонические версии — список отпечатков в сгенерированном файле моделей, рядом с новыми шаблонами (`dev/anki-models`). Метка в CSS доказательством не считается.
   Сбой любого шага → запись не идёт, ошибка видна. Результат запоминается по адресу Anki И версии типа, только после успеха; случай 4 не мешает записи.
   ⚠️ Новое поле меняет схему: AnkiWeb один раз попросит полную синхронизацию. Поэтому не делаем этого тем, кто окном фразы не пользуется. Предупредить в заметках к версии.
   ⚠️ AnkiConnect молча отбрасывает неизвестные поля — поэтому наличие поля проверяется до записи.
   ⚠️ Старый Flibooster может вернуть прежний шаблон (`--update`); это случай 3 при следующем сохранении — значит, запомненный результат проверяется дёшево, а не навсегда: читать шаблон заново раз за запуск фонового процесса.

## Подходы, которые отвергли

1. Писать видео в «Yomitan Card Type», как сейчас пишется фраза: владелец выбрал Phrases. 2. Обновлять типы у всех сразу: всем придётся полная синхронизация AnkiWeb. 3. Не обновлять шаблон, ждать Flibooster: видео записано, но не видно.

## Проверка

Модульные тесты на таблицу полей, границы выделения, все четыре случая типа, все сбои; шаблон — в изолированной Anki; запись через настоящий AnkiConnect в изолированной Anki, не в Anki владельца.
