# Обогащение карточки Anki при «+» (Flib-club)

Статус: проект, ждёт одобрения владельца. Дата: 2026-11-15. Выходит в версии 0.5.1.

## Зачем

Когда слово добавляют через приложение Flibooster, в Anki приходит богатая карточка: перевод, шесть примеров,
синонимы, часть речи, озвучка и ещё две карточки — ReverseDeck (русский → английский) и Phrases (фраза с пропуском).
Расширение без Flibooster кладёт только то, что есть в словаре. Владелец хочет, чтобы расширение само давало тот же
результат через наш сервер Turmaline Gateway под ключом пользователя. Принцип: «купил ключ — всё работает», без
Flibooster, с любого компьютера с Anki.

Источник правды о подходе — anki_conf `docs/ref/card-enrichment-and-pos.md`. Расширение повторяет Flibooster по
результату, а не по коду.

## Цели, не-цели, анти-цели

- Цели:
  - при «+» базовая заметка «Yomitan Card Type» получает ExampleLLM (JSON обогащения), перевод, если поле пусто, и
    озвучку слова, если своего звука нет;
  - создаются две производные заметки, ReverseDeck и Phrases, с озвучкой и нашими тегами;
  - каждый сбой сообщается отдельно, с понятной причиной.
- Не цели:
  - свой ключ ChatGPT или свой MCP (задача 384);
  - настоящая докупка квоты (задача 385, пока заглушка);
  - обогащение заметок других типов;
  - обогащение уже существующих в Anki заметок задним числом.
- Анти-цели (провал, даже если технически работает):
  - карточка не добавилась из-за сбоя обогащения — обогащение не транзакция, базовая заметка добавляется всегда;
  - квота потрачена дважды, потому что обогатили и расширение, и Flibooster;
  - производные карточки задвоились при повторном «+»;
  - расширение перезаписало типы заметок, которые поставил или обновил Flibooster.

## Ограничения

- Только наш шлюз: `POST /v1/openai/chat/completions` и `POST /v1/text-to-speech/{voice_id}` под `Bearer tpk_…`
  (память 4000, 4002, 4004). Flibooster не участвует.
- Квота: ChatGPT в деньгах ($1 в месяц платный, $0.05 демо); озвучка в символах (25 000 в месяц платный, 500 демо),
  попадание в кэш шлюза бесплатно.
- Промпты `enrichment`, `phrases`, `find_form` — дословные копии из anki_conf `configs/llm_queries.yaml` в коммите
  `a62faa63e`, модель gpt-4o-mini, temperature 0.4, `response_format json_object`. Значения подставляются через
  `JSON.stringify` (anki_conf #386).
- Озвучка: голос `HCfhOrkFKTGCSl4c8rjs`, тело ровно `{"text","model_id":"eleven_multilingual_v2"}`, без query. Текст =
  NFC(trim(слово)) — тогда работает общий кэш с Flibooster. Тот же голос для русского; качество русского не проверено.
- Типы заметок — дословные копии `internal/ankimodels/models/*.json` из anki_conf с той же меткой ревизии
  `/* ankimodels-rev:… */` в CSS.
- Новые разрешения в манифесте не добавляются: всё идёт через уже объявленные адреса шлюза и AnkiConnect.

## Подходы

- **А. Обогащение делает расширение через шлюз (выбрано владельцем 2026-11-15).** Работает без Flibooster.
  Промпты — копия из Flibooster, источник правды — общий документ.
- **Б. Обогащение делает Flibooster (как сейчас).** Отброшено владельцем: Flibooster может не быть, он может не
  запуститься, его порт может отличаться.
- **В. Серверная операция «обогати слово».** Позже, когда шлюз её сделает: одна копия промпта на сервере. Переход —
  небольшая правка клиента.

## Как устроено

### Поток при «+»

1. Пользователь нажимает «+». Если обогащение включено (настройка ниже) и ключ есть, расширение добавляет к тегам
   базовой заметки `flib_enriched`. Тогда Flibooster её пропускает целиком (anki_conf #391). В остальном addNote — как
   сейчас.
2. После успешного addNote popup зовёт `api.flibEnrichNote({noteId, word, sentence, hasAudio, userTags})`. Дальше всё
   делает service worker, по шагам и **независимо**: сбой одного шага не отменяет остальные.
   1. **Обогащение.** Запрос `enrichment` с `{w: слово, ex: предложение}`. Ответ разбирается терпимо, как у
      Flibooster. `updateNoteFields`: `ExampleLLM` = весь JSON; `Translate` = `tr`, только если поле пусто.
   2. **Озвучка слова.** Только если у заметки нет звука в `Audio`. Шлюз TTS → `storeMediaFile tts_<word>_<noteId>.mp3`
      → `Audio = [sound:…]`.
   3. **ReverseDeck.** Только если есть перевод (из шага 1 или из поля Translate). Нет ли уже заметки с тегом
      `<noteId>_reverse` — проверка через `findNotes`.
      - Поля: Front = перевод; Back = ""; ExampleLLM; EnglishWords = слово + `<br>` + синонимы; `data` — по схеме
        Flibooster v1.0.
      - Колода — колода базовой заметки.
      - Теги: `<noteId>_reverse`, `flib_enriched`, пользовательские теги.
      - Озвучка русского Front → `tts_rev_<id>.mp3` в `Audio` ReverseDeck и в `Audio_Translate` базовой.
   4. **Phrases.** Запрос `phrases`. При необходимости — `find_form`, в порядке Flibooster: target_form → слово → формы
      → find_form → без пропуска. Нет ли уже заметки с тегом `<noteId>_phrases`.
      - Поля: Front с `_____`, Expression, EnglishWord, ExpressionTranslate (+ `<br>🔸 ` + phrase_or_idiom).
      - Озвучка: Audio_expression — всё предложение; Audio_front — пропуск читается как «... ... ...».
      - Теги: `<noteId>_phrases`, `flib_enriched`, пользовательские.
3. Service worker возвращает отчёт `{enrich, audio, reverse, phrases}`. У каждого шага статус `done | skipped | failed`
   и код ошибки.

### Что видит пользователь

В карточке под кнопкой Anki строка состояния:

```
⟳ Обогащаю карточку…
✓ Примеры, синонимы, озвучка · ещё 2 карточки (обратная и фраза)
⚠ Карточка добавлена. Квота переводов на этот месяц исчерпана — Продлить квоту переводов (скоро будет)
⚠ Карточка добавлена. Озвучки нет: квота озвучки исчерпана — Продлить квоту озвучки (скоро будет)
```

- Тексты ошибок те же, что у кнопки «?»: ключ, квота переводов, квота озвучки, лимит запросов, сервер недоступен,
  непонятный ответ.
- Если popup закрыли раньше, чем пришёл отчёт, заметки всё равно доделываются — работа идёт в service worker. Отчёт
  тогда никто не увидит. В v1 так и остаётся (см. «Решает владелец»).

### Типы заметок

- При первом «+» после запуска расширение спрашивает `modelNames`. Если нет «Yomitan Card Type», «ReverseDeck» или
  «Phrases», недостающие создаются через `createModel` из встроенных JSON.
- Существующие типы **никогда не меняются**: обновляет их Flibooster кнопкой «Обновить устаревшие типы».
- В «Yomitan Card Type» уже есть поля `data`, `flib_media` и `ExampleLLM`. Добавление полей в чужую модель, как
  сейчас делает бутстрап `data`/`flib_media`, остаётся как есть.
- Колода: та, что выбрана в настройках карточки. Если её нет в Anki, `addNote` и сейчас сообщает ошибку — не трогаем.
- Если пользователь выбрал другой тип заметки, обогащение не запускается, теги `flib_enriched` не ставятся: как у
  Flibooster, только для «Yomitan Card Type».

### Настройка

- В разделе «Личный ключ» появляется галочка «Обогащать карточки через ChatGPT (тратит квоту ключа)».
  - Включена по умолчанию.
  - Выключена — в Anki идёт только словарь, тега `flib_enriched` нет. Тогда, если запущен Flibooster, он обогатит
    сам по своей настройке.
- Поле `flibService.enrichCards` в схеме настроек. Миграция ставит `true`.

### Состояние (D2, перечислено)

- **Popup, `DisplayAnki`.** `_enrichStatus: Map<noteId, report>` — читатель: строка состояния текущей статьи.
  `_enrichRequestId` для отбрасывания отчёта после смены выдачи.
- **Service worker.**
  - `_flibModelsChecked: boolean` — закешированный результат проверки типов за жизнь воркера; сбрасывается при
    ошибке `createModel` и при смене адреса Anki. Читатель — `flibEnrichNote` перед шагами.
  - `_flibEnrichInFlight: Set<noteId>` — второй вызов для той же заметки ждёт первый. Читатель — `flibEnrichNote`.
- **Anki** — источник правды о дублях: теги-ссылки и `findNotes`.

### Коды ошибок

Новые к тем, что у кнопки «?»:

| Ответ                                                            | Код                   |
| ---------------------------------------------------------------- | --------------------- |
| TTS 429 `{"error":"quota_exhausted","service":"elevenlabs_tts"}` | `tts_quota_exhausted` |
| TTS прочие отказы провайдера                                     | `tts_failed`          |
| `createModel` отказал                                            | `anki_model_failed`   |
| AnkiConnect недоступен посреди шагов                             | `anki_unavailable`    |

## Крайние случаи (P8)

1. Двойное «+» или повторное «+» на ту же заметку — `_flibEnrichInFlight` плюс проверка тегов-ссылок: дублей нет.
2. Кончилась квота ChatGPT — шаги 1 и 4 падают с `llm_quota_exhausted`; озвучка слова и ReverseDeck по переводу из
   поля Translate всё равно делаются; строка состояния говорит о квоте.
3. Кончилась квота озвучки — заметки без звука, кэшированные слова всё равно озвучены (кэш бесплатен).
4. Flibooster запущен и Anki идёт через него — тег `flib_enriched` в addNote. Core пропускает (проверка в
   `params.note.tags`).
5. Пользователь выключил галочку — ни одного запроса к ChatGPT и TTS, нет тега.
6. Popup закрыт во время обогащения — работа в service worker доходит до конца. Воркер в MV3 живёт, пока идут
   fetch; общий бюджет шагов — 90 с, после него оставшиеся шаги пропускаются с кодом `flib_timeout`.
7. Кавычки, HTML и переводы строк в слове или предложении — `JSON.stringify`; в поля Anki идёт текст, HTML из ответа
   ChatGPT экранируется. Исключение — разметка, которую шаблон Flibooster ожидает (`<br>`, `<b>` в items).
8. Ответ ChatGPT без `tr`, с пятью примерами вместо шести, с лишними ключами — сохраняется как есть, производные
   берут что есть. ReverseDeck без перевода не создаётся.
9. Демо-ключ — пускается сервером, пока есть $0.05 и 500 символов.
10. Слово из нескольких слов (фраза) — так же, как у Flibooster: обогащение и Phrases по всей фразе.

## Тесты

- Чистые функции:
  - сборка запросов и разбор ответов `enrichment`, `phrases`, `find_form`;
  - `buildReverseDeckData`;
  - пропуск в предложении (цепочка поиска формы);
  - EnglishWords;
  - тексты для озвучки (NFC, trim, «... ... ...»);
  - имена файлов.
- Клиент шлюза: TTS — ответ `audio/mpeg`, 429 `quota_exhausted` (service `elevenlabs_tts`), 403 текстом, 5xx, сеть.
- Оркестратор с фейковым AnkiConnect и фейковым шлюзом:
  - все шаги проходят;
  - каждый шаг по отдельности падает, остальные доходят;
  - повторный вызов не создаёт дублей;
  - галочка выключена — ни одного запроса;
  - модель не та — ничего;
  - типы заметок ставятся, только если их нет.
- Popup: строка состояния для каждого исхода; отчёт после смены выдачи отбрасывается.
- Живая проверка в Chromium с настоящей Anki и AnkiConnect, без Flibooster, с заглушкой шлюза:
  - «+» на слове даёт три заметки с полями и звуком;
  - повторное «+» не даёт дублей;
  - заметки с тегом `flib_enriched` Flibooster не трогает.

## Уточнения после проверки глазами исполнителя (мои решения, 2026-11-15)

1. **Старый или неполный тип заметки.** Перед шагами расширение сверяет `modelFieldNames` с полями канонического
   типа. Недостающие поля добавляются через `modelFieldAdd`, как сейчас бутстрап добавляет `data` и `flib_media`.
   Шаблоны и CSS не трогаются. Если добавить не удалось, шаг, которому нужно поле, пропускается с кодом
   `anki_model_outdated`. `Audio_Translate` базовой заметки пишется, только если поле пусто.
2. **Метка ревизии.** Скрипт `dev/sync-anki-models.js` копирует три JSON из anki_conf, переводит их в параметры
   `createModel` и ставит метку `/* ankimodels-rev:… */`. Метку он считает JS-портом `modelRevision` из
   `internal/cli/anki_bootstrap_revision.go`. Тест-сторож сверяет порт с эталонными метками, которые один раз
   выдаёт Go-код. Результат кладётся в `ext/data/anki-models/` вместе с коммитом anki_conf, откуда он взят.
3. **Какое слово.** `w` и текст озвучки берутся из отрендеренного поля `Word` новой заметки: снять HTML, `trim`,
   NFC. `ex` — из поля `Example`. Это ровно то, что Flibooster читает из той же заметки (#392), поэтому кэш
   озвучки общий.
4. **Повторное «+».** Защита — от повторного обогащения одной и той же заметки (`noteId`). Если пользователь
   сознательно добавил вторую заметку на то же слово через «Добавить ещё», она обогащается как новая.
5. **Flibooster без #391.** Без проверки версии: реальных пользователей со старым Flibooster нет, у владельца
   следующая сборка с #391. Риск двойного обогащения у старой сборки принимается.
6. **Квота озвучки кончилась посреди шагов.** Остальные клипы всё равно пробуются: попадание в кэш бесплатно и
   работает даже при исчерпанной квоте. Код `tts_quota_exhausted` показывается один раз.
7. **Тег `flib_enriched` ставится до обогащения.** Иначе Flibooster, через который идёт `addNote`, начнёт
   обогащать сам. Если вызов обогащения не дошёл до service worker или упал целиком до первого шага, расширение
   снимает тег (`removeTags`), чтобы заметку мог обогатить Flibooster. Popup, закрытый в первые миллисекунды
   после `addNote`, — принимаемый риск v1.

## Решения владельца (2026-11-15)

1. **Колода и типы заметок ставятся автоматически**, как это делает установщик Flibooster (anki_conf
   `internal/cli/anki_bootstrap.go`, BootstrapInstall):

   - при первом «+» за жизнь service worker — `modelNames`; каждого недостающего из трёх типов `createModel` с меткой
     ревизии; ошибка «already exists» (гонка с Flibooster) — не ошибка;
   - затем `createDeck "Flibooster"` (идемпотентно, сбой не фатален);
   - существующие типы не меняются, кроме добавления недостающих полей (уточнение 1 выше).

   Моё решение: для новых установок колода по умолчанию в настройках карточки — «Flibooster», а не «Default».
   Существующие настройки не меняются.

2. **Отчёт, если popup закрыт раньше конца** — не показываем. Новых разрешений нет.
3. **Русская озвучка тем же голосом**, что английская. Владелец её проверял, качество удовлетворительное.
